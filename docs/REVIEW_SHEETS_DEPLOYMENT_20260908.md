# ชีทตรวจฝาก/ถอนและรายละเอียดลูกค้า

## เตรียมแล้วในโค้ด

- ชีทฝากและถอนใช้ประเภทธุรกรรม ไม่ขึ้นกับว่าเป็นธนาคารหรือ PM
- Export แยกฝาก ถอน รอระบุประเภท (ถ้ามี) และรวม ภายใต้สิทธิ์และตัวกรองเดิม
- รายละเอียด BO/STM แยก User เลขบัญชีลูกค้า ชื่อลูกค้า ท้าย 4 ตัว และรหัสอ้างอิง
- เก็บข้อมูลสองฝั่งใน customer_details ไม่ใช้เลขบัญชีบริษัทเป็นเลขบัญชีลูกค้า
- เลขบัญชีเก็บเป็นข้อความ รักษาศูนย์นำหน้า ค่าที่ขาดไม่เติมเป็นศูนย์
- ใช้สถานะ clarifying เดิมแสดงชื่อ “รอผู้ชี้แจง” ไม่เพิ่มสถานะอนุมัติระหว่างทาง

## ลำดับนำขึ้นใช้งานจริง

1. ฐานข้อมูลเพิ่ม customer_details และวิวเรียบร้อยแล้ว (ยืนยัน 8 กันยายน 2026); การติดตั้งใหม่ใช้ 20260908_exception_customer_details.sql ตามด้วย 20260908_current_exceptions_customer_details.sql
2. อัปเว็บและนำเข้า Worker ที่ rebuild แล้วตามคู่มือรอบเดิม ไม่เปิด Worker ซ้ำ
3. ทดลองบริษัท/วันเดียว ตรวจ customer_details จากผลรันและหน้าเว็บ
4. ตรวจสิทธิ์ Audit และผู้ชี้แจงด้วยบัญชีทดสอบ การเปลี่ยนสถานะต้องบันทึกจริงและไม่ข้ามบริษัท
5. การเติมข้อมูลเคสเก่าต้องวางแผนเฉพาะจุด ไม่รันใหม่ทับคำชี้แจง/สถานะปิดเดิมโดยไม่ตรวจ

## ข้อจำกัด

ยังไม่ได้เปลี่ยนกฎการจับคู่ให้เลขท้าย 4 ตัวเป็นเหตุปิดอัตโนมัติ ยังไม่ได้รัน production หรือแก้ไฟล์ Excel ตัวอย่าง
รายการธนาคารที่ต้นฉบับไม่ระบุลูกค้าให้ตรวจหลักฐาน ไม่อนุมานชื่อลูกค้าจากชื่อเจ้าของบัญชีบริษัท

## ตรวจระบบจริง 8 กันยายน 2026

- ตรวจ information_schema แล้วไม่พบ customer_details ก่อนดำเนินการ
- หลังเชื่อมต่อใหม่ SELECT ยืนยัน exceptions.customer_details เป็น jsonb แล้ว
- ตรวจนิยามวิวจริงก่อนเพิ่ม customer_details ต่อท้าย โดยคงทุกคอลัมน์เดิม เงื่อนไข completed และ join last_run_id; ไม่แก้ grants หรือสถานะเคส
- SQL Editor ยืนยัน 2 แถว: exceptions.customer_details และ v_current_exceptions.customer_details เป็น jsonb ทั้งคู่
- ทดสอบชุดหลักและ regression ของชีทส่งออก/ฟิลเตอร์/บันทึกรอผู้ชี้แจงผ่านทั้งหมด และรวม regression เหล่านี้เข้า npm test
- ยังไม่ได้ commit/push โค้ด นำเข้า Worker หรือเปลี่ยนสถานะเคสจริง
- เพิ่ม regression test การบันทึกรอผู้ชี้แจง: ปฏิเสธผลลัพธ์ว่าง/สถานะผิด และไม่เปิดเคสปิดแล้วกลับมา
