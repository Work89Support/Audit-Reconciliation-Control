# Bulk cross-day workflow

Prepared pairs can be sent as a set. Lead/admin can atomically submit and approve their own prepared pair through the new close RPCs; helper submissions still require a lead/admin decision. Lead/admin can select multiple pending pairs, confirm one shared review note, and approve without reopening every pair. Queue groups company/account/transaction date/document/page. Both native and manual-image decisions retain existing source validation and reservations.

Each request is processed separately and sequentially, not a single hundreds-row transaction. Exact approved receipts are required. Successful rows leave the queue; errors retain their UUID/draft; transient connection failures stop the remaining batch. There is no page reload. Duplicate native STM rows are still blocked server-side. For image-only rows, the system cannot infer transaction identity from the page number: the head must confirm different real transactions are used, not the same PDF transaction repeatedly.

Migration removes only the submitter/reviewer inequality checks for these two cross-day workflows and leaves authenticated role/company/source protections intact. Decision functions still restrict approvals to lead/admin. Existing pending requests can therefore be approved by their submitting head; assistants cannot approve their own or anyone else's request. Each original decision is written to the existing audit log. Direct close is transactional per pair.

Tests: cross-day-bulk-head.test.cjs mock batch transport; cross-day-image-db.test.mjs executes migrations with synthetic PostgreSQL data and checks direct image closure, idempotence, helper separation, unchanged sources, reservations and original rerun guards. Actual native submit/decision/guard functions also execute through direct-close, including rollback on validator rejection; the native parser validator alone is stubbed in that fixture. This is not a full Supabase or multi-session concurrency test. No production cases are closed during testing. Deployment requires the SQL migration plus matching client release.
