# จับคู่ข้ามบัญชีภายในบริษัท 7M — 6 พฤศจิกายน 2026

ตามคำสั่งผู้ใช้ เปิดให้เลือกทุกบัญชี BO ของ 7M ในบริษัทเดียวกัน แทนกฎเดิมที่บังคับบัญชีเดียวกัน

## พฤติกรรม

- รายชื่อบัญชีมาจาก BO ในผลหลักที่ยืนยันแล้วของบริษัทและวันที่เลือก รวมบัญชีที่ไม่มีเคสเปิด ไม่อ้างผลรันเก่าหรือ master ที่เดาขึ้น
- แสดงรายชื่อบัญชีก่อนตรวจเงื่อนไขคู่ ถ้าไม่มีเคสเปิดหรือคู่ไม่ผ่าน ให้บอกเหตุผลแทนการซ่อนบัญชี
- ข้ามบัญชี: STM/PM โอนออก ↔ BO รับเข้า หรือ STM/PM รับเข้า ↔ BO โอนออก โดยอ่านประเภทดำเนินการจริงใน BO ก่อนหมายเหตุ
- บัญชีเดียวกันยังใช้การปรับเข้า ↔ รับเข้า และปรับออก ↔ โอนออกตามเดิม
- ทุกคู่ต้องเป็น 7M บริษัทเดียวกัน, THB, ยอดตรง, วันเดียวกัน, เวลาครบและห่างไม่เกิน 5 นาที, ต้นทางอยู่ในผลหลักปัจจุบันและอ่านสำเร็จ
- ไม่ใช้รายการที่ปิด ถูกจอง มีคำขอปิด ถูกแทนด้วยผลใหม่ หรือมีความเสียหาย ไม่สร้าง BO/เคสจำลองเพื่อให้จับคู่ได้
- เจ้าหน้าที่ส่งคำขอตามสิทธิ์ หัวหน้า/ผู้ดูแลจึงปิดคู่ได้ รายการต้นทางและประวัติชี้แจงคงเดิม
- เปิดหน้าต่าง ค้นหา และเลือกบัญชีเป็นการอ่านเท่านั้น ต้องเลือกเหตุผลและติ๊กยืนยันก่อนส่ง/ปิด
- ขอบเขตนี้เป็นการจับคู่เคส BO ↔ STM/PM ไม่จับ STM ↔ STM และไม่แก้ engine หรือผลกระทบยอด

## การติดตั้ง

1. ตรวจผล unit, PostgreSQL จำลอง และ Chromium ของ branch ให้ผ่านก่อน
2. ติดตั้ง `supabase/20261106_7m_internal_cross_account_pair.sql` หลัง migration เดิมทั้งหมดใน Supabase เป้าหมาย ไฟล์นี้เปลี่ยนเฉพาะนิยามฟังก์ชัน ไม่สั่งปิดหรือแก้เคสใด
3. นำหน้าเว็บรุ่นเดียวกันขึ้นระบบ (`index.html` เปลี่ยน cache version ทั้ง `supabase.js` และ `manual-pairing.js`)
4. ตรวจ production แบบอ่านอย่างเดียว: เปิดเคส 7M → จับคู่ข้ามบัญชีภายในบริษัท → ค้นหา → เลือกบัญชี BO ตรวจบัญชีและข้อความเหตุผล ห้ามกดส่ง/ปิดในการตรวจ release นี้

หากยังไม่ได้ติดตั้ง SQL ห้ามถือว่ารุ่นหน้าเว็บเพียงอย่างเดียวใช้งานได้ครบ และห้ามแก้หรือปิดเคสจริงเพื่อทดสอบ
