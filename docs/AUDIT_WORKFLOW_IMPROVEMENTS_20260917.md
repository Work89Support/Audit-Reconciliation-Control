# ปรับ Flow Audit — 17 กันยายน 2026

## สิ่งที่เปลี่ยน
1. จำวันที่ตรวจต่อบริษัท พร้อมตัวกรอง หน้า และสถานะที่เตรียมไว้ระหว่างรีเฟรชภายในหน้า ไม่ย้อนกลับวันนี้
2. ติ๊กหลายเคส เตรียมสถานะ แล้วกดบันทึกครั้งเดียว มีสรุปให้ยืนยันและรายงานผลรายเคส ไม่เปิดหน้ารายละเอียดเพียงเพราะเลือกสถานะ
3. ปิดเคสยังตรวจสิทธิ์ ข้อมูลล่าสุด แหล่ง BO/PM และการใช้ธุรกรรมซ้ำ ไม่ใช้ยอดเท่ากันอย่างเดียว
4. ส่งชี้แจงเป็นชุดได้ เคสเข้าชีทรอคำตอบโดยไม่ส่งข้อความภายนอกอัตโนมัติ
5. Audit/หัวหน้า Audit ตอบชี้แจงในบริษัทที่มีสิทธิ์ได้ ระบุว่าเป็นคำตอบจาก Audit/แอดมิน ไม่ใช่การอนุมัติปิด
6. ค้นเอกสารตามชื่อ/หัวข้อเมล/ผู้ส่ง เลือกช่วงวัน Preview ใช้ไฟล์เดิมกับหลายเคสได้ และดูเคสที่เคยใช้ไฟล์นั้น

## Flow
รับเมล → เก็บไฟล์ → ตรวจบริษัท/วัน/ฝากถอน → อ่านไฟล์และตรวจความครบ → กระทบยอด
- ไฟล์ไม่ครบ/อ่านไม่ได้: รอไฟล์หรือแก้ไฟล์
- คู่ชัดเจน: จับคู่สำเร็จ; exception ใช้เกณฑ์หลักฐานก่อนปิด
- คู่กำกวม: รอ Audit ตรวจ
- ไม่พบคู่เมื่อไฟล์ครบ: รอชี้แจง → ตอบพร้อมหลักฐาน → Audit ตรวจ → ปิดหรือขอเพิ่ม

## Worker อัตโนมัติ: เตรียมโค้ดแล้ว แต่ยังไม่เปิดใน n8n จริง
audit-case-policy.js และสคริปต์ sync-worker-audit-policy.mjs ใช้กับผลใหม่เท่านั้น:
- quality ผ่าน ไฟล์ครบ มี match evidence ครบ
- ปิดเฉพาะถอนที่ผ่านเกณฑ์อ้างอิงต้นทางเดียวกัน ไม่มีซ้ำ ต่างเวลาไม่เกิน 60 นาที
- missing_bo/missing_stm ที่มีต้นทางจริง ไม่มีคู่ตรงข้ามกำกวม ส่งเป็น clarifying
- ไม่เปลี่ยนเคสที่คนตรวจแล้ว ไม่เพิ่ม matched count เมื่อปิดเคส
- ไม่ครอบคลุมการปิดอัตโนมัติทุกระบบ/ทุกกรณีข้ามวัน/แบ่งจ่าย
ต้องทดสอบ payload และ finish contract ของ Worker จริงก่อนเปิด ไม่ import workflow ทั้งชุดทับของจริง

## ตารางเวลา
เส้นทาง: Gmail → Supabase Storage/source_files → parser/OCR → คิวบริษัท/วัน → Worker → recon_runs/exceptions → ชี้แจง/รายงาน

| งาน | ค่าที่อยู่ใน repository | ผลตรวจ live |
|---|---|---|
| รับเมล | ทุก 10 นาที | workflow Published; ยังไม่ยืนยัน poll parameter live |
| Dispatcher | 08:00, 16:30, 19:00 Asia/Bangkok | ยังไม่ Published; ตรวจ cron แรกตรง 08:00/19:00 |
| Worker | รับงานจาก Dispatcher | Published แต่ timer ทุก 10 นาที Deactivated |
| จับคู่ไฟล์ชี้แจง | 09:30 | workflow Published; ยังไม่ยืนยันเวลา live |
| แจ้งสรุป Telegram | 08:15, 17:05, 19:15 | workflow Published; ยังไม่ยืนยันเวลา live |

เวลาจบงานขึ้นกับปริมาณไฟล์/OCR/คิว ไม่ใช่เวลา trigger และไม่ควรใช้ runtime เฉลี่ย n8n เป็น SLA ทุกบริษัท
ห้ามเปิด timer Worker และ Dispatcher ซ้ำโดยไม่ตรวจคิวและงานที่กำลังรัน
