Audit AI Reconciliation — ทำครั้งเดียว ใช้ได้ตลอด ประมาณ 40–60 นาที

·ภาพรวมว่าอะไรทำงานตรงไหน

Gmail work.ltd89 label AUDIT 2→ n8n Cloud (ทุก 10 นาที)→ แตก .zip→ Supabase Storage + Google Drive→ ทะเบียนไฟล์ใน Supabase→ ระบบ Audit อ่านและกระทบยอด
ส่วนทำอะไร
n8n Cloudเฝ้าเมล ดึงไฟล์แนบ แตก zip อัปขึ้น Storage และ Drive แล้วบันทึกทะเบียนว่ามีไฟล์อะไรเข้ามาของบริษัทไหน วันไหน
Supabaseเก็บไฟล์ต้นฉบับ (Storage) + ฐานข้อมูลทะเบียนไฟล์ ผลกระทบยอด รายการผิดปกติ อัตราแลกเปลี่ยน ความเสียหาย และ audit log
Google Driveสำเนาไฟล์ต้นฉบับไว้ให้คนเปิดดูเองได้ตามปกติ
ระบบ Auditดึงไฟล์จาก Storage มาแปลงในเบราว์เซอร์ กระทบยอด ออกเอกสารชี้แจง แล้วเขียนผลกลับ Supabase
ตัวอ่านไฟล์ทั้งหมด (xlsx, statement PDF, กฎธุรกิจ) อยู่ในระบบ Audit อยู่แล้วและทดสอบกับไฟล์จริงวันที่ 19/07 ผ่านแล้ว จึงไม่ต้องย้ายโค้ดไป n8n — n8n ทำหน้าที่ขนไฟล์กับทำทะเบียนอย่างเดียว ซึ่งพังยากกว่ามาก

1สร้างโปรเจกต์ Supabase

ฟรีสำหรับปริมาณงานระดับนี้ (ฐานข้อมูล 500 MB + Storage 1 GB)

  1. เข้า supabase.com → Start your project → ล็อกอินด้วย GitHub หรือ Google
  2. กด New project
    • Name: audit-reconciliation
    • Database Password: ตั้งรหัสยาว ๆ แล้วเก็บไว้ให้ดี
    • Region: Southeast Asia (Singapore) — ใกล้ไทยที่สุด
  3. รอสร้างเสร็จประมาณ 2 นาที

สร้างตารางทั้งหมด

  1. เมนูซ้าย → SQL Editor → New query
  2. เปิดไฟล์ supabase/schema.sql ที่ให้มา คัดลอกทั้งไฟล์ วางลงไป
  3. กด Run (หรือ Ctrl+Enter)
  4. ควรขึ้น Success. No rows returned

สคริปต์นี้สร้างให้ครบ: ตาราง 8 ตาราง, view 2 อัน, Storage bucket audit-files, RLS ทุกตาราง และ trigger เก็บประวัติการแก้อัตราแลกเปลี่ยน — รันซ้ำได้ไม่พัง

สร้างผู้ใช้สำหรับทีมออดิท

  1. Authentication → Users → Add user → Create new user
  2. ใส่อีเมลและรหัสผ่านของแต่ละคน ติ๊ก Auto Confirm User
  3. ทำซ้ำให้ครบทุกคนที่ต้องใช้ระบบ
สำคัญ: ทุกตารางเปิด RLS ไว้ ถ้าไม่ล็อกอินจะอ่านข้อมูลไม่ได้เลย — ตั้งใจให้เป็นแบบนี้ เพราะเป็นข้อมูลบัญชีธนาคารของลูกค้าจริง

เก็บค่า 3 อย่างนี้ไว้

Project Settings → API

2เตรียมโฟลเดอร์ใน Google Drive

  1. สร้างโฟลเดอร์ใน Drive เช่น Audit ไฟล์ประจำวัน
  2. เปิดโฟลเดอร์ แล้วดู URL: drive.google.com/drive/folders/1AbCdEf...
  3. ส่วนที่หนาคือ Folder ID เก็บไว้ใช้ในขั้นถัดไป

3แก้ค่าในไฟล์ workflow ก่อน import

เปิด n8n/audit-mail-ingest.json ด้วย Notepad แล้วใช้ Find & Replace

ค้นหาแทนที่ด้วย
{{ $vars.SUPABASE_URL }}Project URL ของคุณ เช่น https://xxxx.supabase.co
{{ $vars.SUPABASE_SERVICE_KEY }}service_role key
{{ $vars.DRIVE_FOLDER_ID }}Folder ID จากขั้นที่ 2
ถ้าแพ็กเกจ n8n Cloud ของคุณมีเมนู Variables จะตั้งค่าตัวแปรทั้ง 3 ตัวไว้ตรงนั้นแทนก็ได้ ไม่ต้องแก้ไฟล์ (Variables เป็นฟีเจอร์ของแพ็กเกจแบบเสียเงิน)

4ตั้งค่า n8n Cloud

4.1 สร้าง Credentials 3 ตัว

เมนูซ้าย → Credentials → Add credential

ชนิดตั้งค่ายังไง
Gmail OAuth2 n8n Cloud มีปุ่ม Sign in with Google ให้เลย กดแล้วเลือกบัญชี work.ltd89@gmail.com → อนุญาตสิทธิ์อ่านเมล
ตั้งชื่อว่า Gmail (work.ltd89)
Google Drive OAuth2 เหมือนกัน เลือกบัญชีที่เป็นเจ้าของโฟลเดอร์จากขั้นที่ 2
ตั้งชื่อว่า Google Drive
Header Auth Name: Authorization
Value: Bearer <service_role key> (มีคำว่า Bearer เว้นวรรคแล้วตามด้วยคีย์)
ตั้งชื่อว่า Supabase service_role

4.2 Import workflow

  1. Workflows → Add workflow → จุดสามจุดมุมขวาบน → Import from File
  2. เลือกไฟล์ audit-mail-ingest.json ที่แก้ค่าแล้ว
  3. เปิดทีละโหนดที่ขึ้นสามเหลี่ยมเตือนสีแดง แล้วเลือก Credential ที่สร้างไว้ให้ตรง
    • Gmail: เมลใหม่ใน AUDIT 2 → Gmail (work.ltd89)
    • Supabase: … ทั้ง 3 โหนด → Supabase service_role
    • Google Drive: สำรองไฟล์ → Google Drive
  4. ที่โหนด Gmail Trigger กด Label Names or IDs แล้วเลือก AUDIT 2 จากรายการ (n8n จะดึงชื่อ label มาให้เอง)

4.3 ทดสอบ

  1. กด Test workflow ที่มุมล่าง
  2. ควรเห็นข้อมูลไหลผ่านทุกโหนดเป็นสีเขียว
  3. ไปดูที่ Supabase → Table Editor → mail_batches และ source_files ควรมีแถวขึ้นมา
  4. ไปดู Storage → audit-files ควรมีโฟลเดอร์ 2026-07-20/AT4/ พร้อมไฟล์

4.4 เปิดใช้จริง

สลับสวิตช์ Inactive → Active มุมขวาบน จากนี้ n8n จะเช็คเมลให้ทุก 10 นาทีเอง

ปรับความถี่ได้ที่โหนด Gmail Trigger → Poll Times เช่น ถ้าเมลเข้าวันละครั้งตอนเช้า ตั้งเป็นทุก 1 ชั่วโมงก็พอ ประหยัดโควตา

5ต่อระบบ Audit เข้ากับ Supabase

  1. เปิดระบบ Audit → เมนู คลังไฟล์จากเมล
  2. กรอก
    • Supabase URL — Project URL
    • anon public key — ไม่ใช่ service_role
    • Storage bucket — audit-files
    • อีเมล / รหัสผ่าน — ผู้ใช้ที่สร้างไว้ในขั้นที่ 1
  3. กด ทดสอบการเชื่อมต่อ ควรติ๊กเขียวครบ 5 ข้อ
  4. กด บันทึกและล็อกอิน

จากนั้นหน้านี้จะขึ้นรายการเมลที่ n8n ดึงมาแล้ว พร้อมไฟล์ทั้งหมดของแต่ละเมล กด เลือกที่ยังไม่ได้อ่าน → ดึงเข้าระบบ ระบบจะโหลดไฟล์จาก Storage มาแปลงและกระทบยอดให้ทันที

6ตรวจว่าใช้ได้จริง

ตรวจอะไรต้องเห็นอะไร
Supabase → Table Editor → mail_batchesมีแถวของเมล พร้อม company เป็น AT4/SK8/FR8 และ business_date ถูกต้อง
source_filesไฟล์ครบทุกไฟล์ รวมไฟล์ที่อยู่ใน .zip และคอลัมน์ kind ระบุชนิดถูก
Storage → audit-filesโฟลเดอร์แยกตามวันที่และบริษัท
Google Driveไฟล์เดียวกันอยู่ในโฟลเดอร์ที่ตั้งไว้
ระบบ Audit → คลังไฟล์จากเมลเห็นเมลทุกฉบับ กดดึงเข้าระบบแล้วอัตราจับคู่ขึ้นในแดชบอร์ด

อาการสาเหตุและวิธีแก้
n8n ไม่เห็นเมลใหม่Gmail Trigger ดึงเฉพาะเมลที่เข้าหลังตอนเปิด Active — ทดสอบด้วยการส่งต่อเมลเก่าเข้ามาใหม่ หรือกด Test workflow ซึ่งจะดึงเมลล่าสุดมาให้
อัปไฟล์แล้ว 400 Bad Requestชื่อไฟล์มีอักขระที่ Storage ไม่รับ — โหนด เดาชนิดไฟล์และตั้ง path กรองให้แล้ว ถ้ายังเจอให้ดูค่า storage_path ในผลลัพธ์ของโหนดนั้น
ระบบ Audit ขึ้น "ไม่มีสิทธิ์อ่านข้อมูล"ยังไม่ได้ล็อกอิน หรือใส่ service_role แทน anon key — ออกแล้วล็อกอินใหม่ด้วย anon key
ไฟล์ใน zip ชื่อเพี้ยนเป็นตัวประหลาดzip จากโปรแกรมไทยใช้รหัส cp874 — ตัวแตก zip ในระบบ Audit รองรับแล้ว ส่วนใน n8n ถ้าเจอให้ดึงไฟล์ผ่านหน้าคลังไฟล์แทน
เมลหนึ่งฉบับเข้าซ้ำหลายรอบตาราง mail_batches ตั้ง unique ที่ gmail_message_id และ source_files unique ที่ (batch, ชื่อไฟล์, zip) จึงกันซ้ำให้เองอยู่แล้ว
Storage เต็มแพ็กเกจฟรีให้ 1 GB — ไฟล์วันละประมาณ 3–5 MB อยู่ได้ราว 6 เดือน หลังจากนั้นย้ายไฟล์เก่าไป Drive อย่างเดียวแล้วลบใน Storage ได้ เพราะ drive_url ยังอยู่ในทะเบียน
